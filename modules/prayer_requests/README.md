# Интеграция записок и молебнов

Модуль `prayer_requests` задаёт безопасную интеграционную границу между ChurchCMS и внешними системами приёма церковных записок, молебнов и других заявок.

## Capability

Модуль публикует `prayer_requests.submit`.

Внешний адаптер реализует `PrayerRequestProvider` и регистрируется через `PrayerRequestProviderRegistry::register()` во время загрузки своего runtime.

Провайдер сам объявляет поддерживаемые виды заявок как список `code + label`. Ядро ChurchCMS не прошивает закрытый перечень служб и не навязывает одинаковый набор всем приходам.

## Данные заявки

В адаптер передаются только:

- `site_key`;
- публичный ID активной организации-получателя;
- код выбранного вида заявки;
- список от 1 до 100 имён;
- необязательный текстовый комментарий;
- локальный путь возврата.

Имена и комментарий перед передачей очищаются от HTML. Произвольный внешний return URL не допускается.

## Результат адаптера

Адаптер возвращает собственный идентификатор провайдера, внешний ID заявки и необязательный HTTPS URL статуса. ChurchCMS отклоняет HTTP URL и результат от другого provider ID.

## Организационная граница

Перед вызовом адаптера ChurchCMS проверяет, что организация существует, активна и принадлежит указанному `site_key`. Внешний адаптер не получает прямой доступ к БД ChurchCMS.

## Что не входит в границу

- автоматическая трактовка заявки как оплаченной;
- платёжная логика;
- фиксированный богослужебный справочник для всех установок;
- автоматическая публикация персональных данных;
- прямой доступ внешней системы к БД.

Если конкретный провайдер совмещает записки и оплату, платёжная часть должна использовать отдельную границу `donations.checkout` и собственный подтверждённый контракт провайдера.

## Проверка

```bash
php tools/prayer-requests-boundary-smoke.php
```

Smoke проверяет capability, список служб адаптера, нормализацию plain text, organization/site_key boundary, ограничения количества имён, локальный return path и HTTPS status URL.
