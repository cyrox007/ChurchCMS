# Модуль Pages

Pages хранит иерархическое дерево постоянных страниц сайта. Каждый узел имеет
stable public ID, canonical path и nullable-ссылку на локальную организацию-
владельца в том же `site_key`.

## Public API

Доступны read-only endpoints:

```text
GET /api/v1/pages
GET /api/v1/pages/{public_id}
```

Коллекция использует ограниченную пагинацию `page`/`per_page` (не более 100
строк). API возвращает только опубликованные страницы с наступившим
`published_at`. Внешняя проекция содержит stable `id`, `parent_id`,
`organization_owner_id`, canonical `path`, контент и UTC timestamps; внутренние
числовые ключи базы данных не раскрываются.

## Публичные страницы

Опубликованный узел доступен по адресу `/pages/<canonical path>`, включая
вложенные разделы, например `/pages/o-prihode/istoriya`. Финальный wildcard
маршрута принимает один или несколько безопасных slug-сегментов. Контроллер
формирует canonical SEO, а шаблон — breadcrumbs только из опубликованных
предков. Логический шаблон темы: `page.show`.

## Публикация дерева

Дочернюю страницу нельзя опубликовать раньше родительской, а опубликованный
раздел нельзя переместить под черновик. Снятие раздела с публикации переводит в
draft весь его subtree и очищает `published_at`, поэтому в API не остаются
публичные потомки скрытого родителя.

Admin Shell и organization-scoped выбор владельца реализуются следующим
вертикальным срезом.
