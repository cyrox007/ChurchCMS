# Модуль Pages

Pages хранит иерархическое дерево постоянных страниц сайта. Каждый узел имеет
stable public ID, canonical path и nullable-ссылку на локальную организацию-
владельца в том же `site_key`.

## Public API

Доступны read-only endpoints:

```text
GET /api/v1/pages
GET /api/v1/pages/{public_id}
```

Коллекция использует ограниченную пагинацию `page`/`per_page` (не более 100
строк). API возвращает только опубликованные страницы с наступившим
`published_at`. Внешняя проекция содержит stable `id`, `parent_id`,
`organization_owner_id`, canonical `path`, контент и UTC timestamps; внутренние
числовые ключи базы данных не раскрываются.

## Публикация дерева

Дочернюю страницу нельзя опубликовать раньше родительской, а опубликованный
раздел нельзя переместить под черновик. Снятие раздела с публикации переводит в
draft весь его subtree и очищает `published_at`, поэтому в API не остаются
публичные потомки скрытого родителя.

Публичный HTML, Admin Shell и organization-scoped выбор владельца реализуются
поэтапно.

## Admin Shell и RBAC

Раздел `/admin/pages` использует отдельные права `pages.read`, `pages.create`,
`pages.edit` и `pages.publish`. Для scope-ограниченной роли доступны только
страницы и активные организации-владельцы внутри назначенной organization
ветки. Изменение slug или родителя и снятие раздела с публикации затрагивают
поддерево, поэтому контроллер проверяет доступ ко всем его узлам.

Редактор атомарно сохраняет содержимое, положение в дереве, порядок и
организацию-владельца. Нельзя выбрать недоступного владельца или родительскую
страницу из соседней ветки. Legacy-страницы без владельца доступны только
глобальной роли.

Публичный HTML по canonical path остаётся следующим вертикальным срезом.
