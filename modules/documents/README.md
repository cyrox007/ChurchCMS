# Документы

Модуль закладывает P0-фундамент каталога документов с обязательной
принадлежностью к локальной organization unit.

## Карточка документа

`documents` хранит:

- stable public ID;
- `site_key`;
- обязательный `owner_organization_public_id`;
- статус;
- название;
- машинный тип документа;
- необязательные номер и дату документа;
- краткое описание;
- даты создания и изменения.

Без явного владельца используется site root.

## Организационная граница

Сервис принимает только активную organization unit того же `site_key`.
Составной внешний ключ
`(site_key, owner_organization_public_id)` закрепляет ту же границу на уровне
PostgreSQL/MySQL.

Архивирование сохраняет stable public ID вместо hard-delete и возвращает
видимость в `private`.

## Публикация и видимость

Новая карточка всегда создаётся как `draft/private`. Режимы видимости:

- `private` — только локальная редакционная карточка;
- `public` — разрешено локальное публичное представление;
- `federated` — разрешён будущий federation-экспорт.

`public` и `federated` разрешаются только после явной публикации документа.
Снятие с публикации переводит карточку обратно в `draft/private`.
Federation-репозиторий возвращает только `published/federated` записи.

Source-side обмен использует два bounded incremental-потока с составным
курcором `updated_at + public_id`: активные документы и tombstone.
`GET /api/v1/partner/documents` отдаёт только безопасную карточку без пути,
blob и файлового содержимого. `GET /api/v1/partner/documents/tombstones`
сообщает об уходе ранее federated-документа из внешнего представления.

Tombstone создаётся атомарно при `withdraw`, архивировании и переключении
видимости с `federated` на локальную. Возврат в `federated` очищает старый
tombstone, чтобы новый принимающий узел не применил устаревшее удаление.

`FederationDocumentSyncWorker` принимает оба потока в независимое состояние
`documents`, сохраняет удалённые карточки как remote projection типа
`document` и не превращает их в локальные канонические Documents. Частичный
сбой tombstone-потока сохраняет уже подтверждённый курсор активного потока;
повторный запуск продолжает незавершённую часть.

## Файл документа

Этот foundation намеренно **не хранит filesystem path и не считает файл
загруженным**.

Файловое вложение будет отдельной связью с Media после реализации безопасного
upload/storage pipeline. Это позволяет не смешивать карточку документа,
редакционный lifecycle и небезопасное прямое управление путями к файлам.

## Следующие инкременты

- версии/замены файла;
- агрегированная Documents-лента с сохранением исходного узла.
