# Интеграции образовательного профиля

Модуль `education_integrations` предоставляет ограниченные адаптеры Moodle и Open Journal Systems (OJS). Он не хранит пароли пользователей внешних систем и не предоставляет произвольный прокси к их API.

## Общие правила безопасности

- разрешён только HTTPS;
- базовый адрес не может содержать логин, пароль, query или fragment;
- `localhost` и приватные/reserved IP-адреса отклоняются;
- перед реальным запросом доменное имя разрешается повторно, приватные/reserved адреса блокируются;
- HTTP redirects не выполняются;
- токены не передаются в URL;
- наружу доступны только заранее определённые операции адаптера.

Секреты должны храниться средствами защищённого конфигурационного слоя ChurchCMS. Адаптер получает токен уже после расшифровки и никогда не возвращает его в результатах.

## Moodle

`MoodleEducationAdapter` использует стандартный Web Service REST endpoint:

`/webservice/rest/server.php`

Токен передаётся в теле POST-запроса. Адаптер поддерживает только:

- `core_webservice_get_site_info` — проверка соединения и сведения о сайте;
- `core_course_get_courses` — получение списка курсов.

На стороне Moodle администратор должен создать External Service и разрешить используемому токену нужные функции. ChurchCMS не расширяет права токена и не позволяет указать произвольный `wsfunction`.

## Open Journal Systems

`OjsEducationAdapter` использует REST API OJS и API token в заголовке:

`Authorization: Bearer <token>`

Поддерживаются:

- `/_/api/v1/contexts` — получение доступных журналов/контекстов на уровне сайта;
- `/{journalPath}/api/v1/submissions` — получение заявок указанного журнала.

Путь журнала проходит отдельную проверку и не может содержать `/`, query или fragment.

Для API token OJS на стороне OJS должен быть настроен секрет API. Необходимо использовать поддерживаемую и исправленную версию OJS и регулярно ротировать API keys.

## Расширение

Новый внешний LMS/журнальный движок реализует `EducationPlatformAdapter`. Для сетевых тестов используется `EducationPlatformHttpClient`, поэтому smoke-тесты не требуют доступа во внешний интернет и могут проверять точный URL, заголовки и расположение токена.
