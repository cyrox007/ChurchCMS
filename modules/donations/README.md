# Интеграция пожертвований

Модуль `donations` задаёт безопасную границу между ChurchCMS и внешними платёжными системами. ChurchCMS не реализует собственный эквайринг и не принимает данные банковских карт.

## Capability

Модуль публикует `donations.checkout`.

Внешний адаптер реализует `DonationProvider` и регистрируется через `DonationProviderRegistry::register()` во время загрузки своего runtime.

Запрос на создание внешней платёжной операции содержит только:

- `site_key`;
- публичный ID активной организации-получателя;
- сумму в минимальных единицах валюты;
- трёхбуквенный код валюты;
- назначение пожертвования;
- локальный путь возврата после внешней страницы оплаты.

Данные банковских карт, CVC/CVV, платёжные токены клиента и другие реквизиты карты через этот контракт не передаются.

## Требования к адаптеру

Адаптер обязан вернуть:

- собственный идентификатор провайдера;
- внешний идентификатор созданной операции;
- HTTPS-адрес внешней платёжной страницы.

ChurchCMS отклоняет HTTP-адреса и несовпадающий идентификатор адаптера. Путь возврата пользователя должен быть локальным, поэтому адаптер не может использовать этот параметр как open redirect.

## Организационная граница

Перед вызовом адаптера ChurchCMS проверяет, что организация-получатель существует, активна и принадлежит указанному `site_key`. Адаптер не получает прямой доступ к БД ChurchCMS.

## Что намеренно не входит в этот модуль

- хранение карточных данных;
- собственная платёжная форма;
- самодельная обработка банковских webhook;
- логика конкретного банка или агрегатора;
- автоматическое признание платежа успешным без подтверждённого контракта конкретного провайдера.

Webhook/status API конкретных систем должны добавляться их адаптерами и проходить отдельную проверку подписи и идемпотентности.

## Проверка

```bash
php tools/donations-boundary-smoke.php
```

Smoke проверяет доступность capability, регистрацию адаптера, нормализацию валюты, границу организации/site_key, локальный return path и обязательный HTTPS redirect.
