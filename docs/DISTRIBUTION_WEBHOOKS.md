# Исходящие webhooks внешнего распространения

ChurchCMS может отправлять подписанные события внешним системам после публикации или снятия материала.

## События

Поддерживаются:

- `publication.published` — материал опубликован вручную или отложенным worker;
- `publication.withdrawn` — материал снят с публикации.

Сбой внешнего endpoint не блокирует локальную публикацию и не меняет её статус.

## Payload

В очередь попадает только безопасная проекция публикации:

- `public_id`;
- `site_key`;
- тип и статус;
- slug, заголовок и краткое описание;
- время публикации и обновления;
- canonical URL, если настроен URL сайта;
- идентификатор организации-владельца.

Полный `body_html`, пароли, токены и другие секреты не передаются.

## Подпись

Каждый запрос содержит заголовки:

- `X-ChurchCMS-Event`;
- `X-ChurchCMS-Event-Id`;
- `X-ChurchCMS-Timestamp`;
- `X-ChurchCMS-Signature`.

`X-ChurchCMS-Signature` имеет формат `sha256=<hex>` и вычисляется как HMAC-SHA256 от строки `<timestamp>.<raw-json-payload>` с secret конкретного endpoint.

Получатель должен проверять подпись через constant-time сравнение и отклонять слишком старые timestamp, чтобы уменьшить риск повторного воспроизведения запроса.

## Безопасность endpoint

Разрешены только HTTPS URL. Запрещены localhost, literal private/reserved IP, credentials и fragment.

Непосредственно перед запросом ChurchCMS разрешает DNS-имя, отклоняет private/reserved адреса и закрепляет уже проверенный IP через `CURLOPT_RESOLVE`. Редиректы отключены. Это не позволяет переадресовать запрос на внутренний адрес через обычный redirect или повторное DNS-разрешение после проверки.

Secret хранится в БД только в зашифрованном виде через `SecretVault` и не показывается обратно в Admin Shell.

## Очередь и повторы

Состояния доставки:

- `pending` — ожидает первой попытки;
- `retry` — запланирован повтор;
- `delivered` — endpoint вернул HTTP 2xx;
- `dead` — доставка окончательно остановлена.

Повторяются сетевые ошибки, HTTP 408, 425, 429 и 5xx. Прочие 4xx считаются постоянной ошибкой. Максимум выполняется пять попыток с увеличивающейся задержкой.

Worker запускается командой:

```bash
php bin/distribution-webhooks.php --limit=25
```

На рабочем сервере его следует запускать регулярно через cron или systemd timer. Повторный запуск безопасен: worker выбирает только `pending/retry`, у которых наступил `next_attempt_at`.

## Admin Shell

Раздел **Исходящие webhooks** использует два права:

- `distribution_webhooks.read` — просмотр endpoint'ов и истории доставок;
- `distribution_webhooks.manage` — создание, включение и отключение endpoint'ов.

Для ротации secret рекомендуется создать новый endpoint, проверить доставку и затем отключить старый. Старый secret интерфейсом не раскрывается.
