# Content revisions

ChurchCMS хранит редакционную историю страниц и публикаций в общей таблице
`content_revisions`, но снимок формируется доменным модулем.

## Что попадает в историю

Для Pages сохраняются:

- заголовок и название для меню;
- slug и родитель;
- очищенный HTML содержимого;
- порядок;
- организация-владелец.

Для Publications сохраняются:

- тип, slug, заголовок и краткое описание;
- очищенный HTML;
- автор;
- организация-владелец;
- категории и теги;
- syndication targets;
- флаг комментариев.

Статус публикации, `published_at` и расписание в revision не входят.
Восстановление текста не должно само публиковать материал, снимать его с
публикации или менять дату публикации.

## Сохранение

Снимок текущего состояния создаётся внутри той же транзакции, что и изменение.
Если основное сохранение откатывается, revision также не остаётся в базе.

Повторный одинаковый снимок не создаётся, если он совпадает с последним
revision.

## Восстановление

Admin Shell показывает только номер revision, дату и старый заголовок.
Сырой `snapshot_json` в шаблон не передаётся как HTML.

Восстановление:

1. требует `pages.edit` или `publications.edit`;
2. повторно проверяет organization scope;
3. для Pages дополнительно проверяет доступ к сохранённому родителю;
4. применяет данные через обычный доменный service;
5. перед применением автоматически сохраняет текущую версию;
6. пишет отдельное audit-событие.

История поэтому не переписывается назад: restore создаёт новое текущее
состояние, а предыдущая текущая версия остаётся доступной для следующего
восстановления.

## Ограничения первой версии

Revision хранит только редакционные данные Pages/Publications. SEO overrides,
настройки внешних каналов и lifecycle-состояния пока не входят в snapshot.

Один snapshot ограничен 1 МиБ. В Admin Shell выводятся последние 50 revisions.
