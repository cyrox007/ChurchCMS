# Миграция из VPDS

## Назначение

ChurchCMS 1.0 принимает legacy-данные VPDS через проверяемый промежуточный manifest. Импортёр не пытается угадывать структуру произвольной старой базы и не переносит небезопасные парольные хэши.

Поддерживаемый контракт входных данных:

- `format`: `churchcms-vpds-export`;
- `version`: `1`;
- `source.site_id`: стабильный идентификатор исходного сайта;
- `users`: пользователи для безопасного сопоставления;
- `content`: публикации;
- `media`: локальные файлы с SHA-256;
- `redirects`: старые и новые локальные пути.

Если реальная установка VPDS имеет другую схему, сначала нужен отдельный экспортёр/преобразователь в этот manifest. Сам импортёр ChurchCMS при несовместимом формате должен завершаться с диагностикой, а не изменять код или данные наугад.

## Пример manifest

```json
{
  "format": "churchcms-vpds-export",
  "version": 1,
  "source": {
    "site_id": "legacy-parish"
  },
  "users": [
    {
      "id": "42",
      "email": "editor@example.org",
      "name": "Редактор"
    }
  ],
  "content": [
    {
      "id": "1001",
      "type": "article",
      "status": "published",
      "slug": "history",
      "title": "История прихода",
      "excerpt": "Краткое описание",
      "body": "<p>Текст материала</p>",
      "author_id": "42",
      "published_at": "2021-05-01T10:00:00+03:00",
      "categories": ["История"],
      "tags": ["приход"]
    }
  ],
  "media": [
    {
      "id": "501",
      "path": "2021/05/photo.jpg",
      "name": "photo.jpg",
      "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
      "bytes": 123456,
      "title": "Храм",
      "alt": "Фасад храма"
    }
  ],
  "redirects": [
    {
      "from": "/old/history.html",
      "to": "/publications/history"
    }
  ]
}
```

## Сопоставление данных

### Пользователи

Legacy-пароли и любые поля `password`, `password_hash`, `hash` не переносятся.

Пользователь VPDS сопоставляется только с уже существующей активной административной учётной записью ChurchCMS по нормализованному email. Совпадение принимается только когда найден ровно один пользователь и его роли позволяют работу с целевой организацией/сайтом. Неоднозначные и неизвестные пользователи остаются несопоставленными и попадают в отчёт.

Это намеренное ограничение безопасности: после миграции доступ выдаётся штатными средствами ChurchCMS, а не переносом старых секретов.

### Публикации

Поля `type`, `status`, `slug`, `title`, `excerpt`, `body`, `author_id`, `published_at`, категории, теги и цели распространения преобразуются в штатный контур Publications.

Поддерживаемые основные типы ChurchCMS: `news`, `article`, `announcement`, `sermon`, `interview`, `document`. Неизвестный тип безопасно приводится к `article`.

Материал получает владельцем выбранную организацию ChurchCMS. Повторный импорт того же объекта с тем же checksum пропускается; изменённый объект обновляет ранее созданную публикацию, когда соответствие однозначно.

### Media

Media читается только из каталога, переданного через `--media-root`.

Импортёр:

- запрещает абсолютные пути, `..`, NUL и выход из корневого каталога;
- требует SHA-256 в manifest;
- повторно вычисляет SHA-256 файла перед передачей в Media;
- при наличии `bytes` сверяет размер;
- сохраняет файл через штатный `MediaUploadService` и `MediaBlobStorage`;
- после записи повторно сверяет SHA-256 сохранённого Media;
- повторно использует уже существующий неархивный Media той же организации с тем же SHA-256.

Отсутствующий файл, неверная контрольная сумма или несовпадающий размер считаются ошибкой импорта и отражаются в отчёте.

### URL и redirect

Входные redirect принимают только локальные пути. Внешние URL, self-redirect и циклические цепочки отклоняются.

Сохранение выполняется через штатный `RedirectService`, поэтому продолжают действовать ограничения ChurchCMS на зарезервированные системные пути и цепочки redirect.

Локальные `href`/`src` в `body` и `excerpt` переписываются по известной карте redirect. Несопоставленные локальные ссылки не удаляются молча: они сохраняются и попадают в диагностику `vpds_unresolved_link`.

## Идемпотентность

Таблица `vpds_import_mappings` хранит для организации, исходного сайта, типа объекта и legacy ID:

- checksum исходной записи;
- public ID созданного объекта ChurchCMS;
- время первого и последнего обновления соответствия.

Это позволяет безопасно повторять импорт после исправления manifest или Media-набора. Неизменённые публикации и Media не создаются повторно.

## Пробный прогон

Перед реальной миграцией обязателен dry-run:

```bash
php bin/vpds-import.php \
  --organization=123 \
  --manifest=/srv/vpds/export/manifest.json \
  --media-root=/srv/vpds/export/media \
  --dry-run \
  --report=/srv/vpds/vpds-dry-run.json
```

Dry-run выполняет проверку структуры manifest, пользователей, путей, контрольных сумм, ссылок и redirect, но адаптеры записи получают флаг пробного режима и состояние идемпотентности не изменяется.

После устранения ошибок выполняется реальный импорт:

```bash
php bin/vpds-import.php \
  --organization=123 \
  --manifest=/srv/vpds/export/manifest.json \
  --media-root=/srv/vpds/export/media \
  --report=/srv/vpds/vpds-import.json
```

## Порядок живой миграции

1. Создать и проверить резервную копию ChurchCMS.
2. Получить неизменяемый экспорт VPDS и Media-каталог.
3. Преобразовать исходную схему в manifest версии 1.
4. Выполнить dry-run.
5. Исправить все ошибки Media, формата и опасных redirect; отдельно просмотреть предупреждения о пользователях и ссылках.
6. Выполнить реальный импорт.
7. Проверить количество публикаций и Media, владельца-организацию, даты, авторов, категории и публичные страницы.
8. Проверить старые URL и redirect.
9. Пройти отчёт по несопоставленным ссылкам и пользователям.
10. При необходимости исправить manifest и безопасно повторить импорт.

## Отчёт

Формат отчёта: `churchcms-vpds-import-report`, версия `1`.

Он содержит:

- `success`;
- признак `dry_run`;
- целевую организацию и `source_site`;
- счётчики пользователей, контента, Media, redirect и несопоставленных ссылок;
- список диагностик с уровнями `warning`/`error`, кодами и контекстом.

Ошибка в одном объекте не скрывается: импортёр продолжает проверку остальных записей, чтобы один dry-run дал максимально полный список проблем.

## Автоматическая проверка

Без БД и сети:

```bash
php tools/vpds-import-smoke.php
```

CI дополнительно проверяет синтаксис всего VPDS-контура и обратимую миграцию в составе общих release-проверок PostgreSQL/MySQL.
