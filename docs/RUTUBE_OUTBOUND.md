# Исходящая публикация в Rutube

## Состояние реализации

ChurchCMS 1.0 содержит полный внутренний контур для исходящей публикации видео в Rutube:

- адаптер объявляет `publish.video`;
- публикация берёт связанное видео из Media через `media.resumable-upload`;
- исходящая очередь, повторные попытки и dead-letter используют общий механизм внешних каналов;
- видео проходит локальную предварительную проверку до обращения к провайдеру;
- ошибки, которые повтором исправить нельзя, сразу переводятся в dead-letter;
- состояние готовности адаптера доступно через общий диагностический контракт;
- фактическая загрузка вынесена в `RutubeUploadTransport`, поэтому подтверждённый партнёрский транспорт подключается без изменения очереди и доменной логики.

Входящая синхронизация Rutube продолжает работать через публичный endpoint `/api/video/person/{id}/` и не зависит от исходящего транспорта.

## Подтверждённые ограничения Rutube

При реализации использованы публичные требования Rutube, актуальные на 13 октября 2026 года:

- максимальный размер видео — 25 ГБ;
- максимальная длительность — 5 часов;
- поддерживаются MP4, AVI, WMV, MOV, FLV, MPEG/MPG, 3GPP, WebM, а также опубликованные Rutube профессиональные форматы/кодеки;
- обложка в Rutube Studio — JPEG/JPG/PNG до 10 МБ и до 1920×1080;
- интерфейс Rutube Studio допускает несколько одновременных загрузок.

Официальные страницы:

- https://rutube.ru/info/upload/
- https://rutube.ru/info/faq/

ChurchCMS не копирует ограничения браузерной Студии на количество одновременных загрузок в свой worker: фактическая параллельность должна определяться официальным машинным контрактом, когда он будет предоставлен.

## Проверка видео до отправки

`RutubeVideoPolicy` проверяет:

1. наличие связанного Media-видео;
2. наличие публичного ID Media;
3. ненулевой размер;
4. размер не более 25 ГБ;
5. MIME-тип из подтверждённого набора видеоформатов;
6. длительность не более пяти часов, если `duration_seconds` уже присутствует в Media payload;
7. наличие заголовка публикации.

Текущий `MediaResumableUploadCapability::publicationVideo()` гарантированно предоставляет ID, MIME, размер и SHA-256. Длительность пока не является обязательной частью Media-контракта, поэтому локальная проверка длительности выполняется только когда это поле известно. Финальный транспорт обязан также учитывать ограничения провайдера и корректно обрабатывать отказ Rutube по длительности.

## Почему ChurchCMS не вызывает скрытые endpoint Rutube Studio

На момент аудита официально опубликованного машинного upload API Rutube обнаружить не удалось. Browser-endpoint Rutube Studio не является стабильным публичным контрактом и не должен использоваться серверной CMS без разрешения провайдера.

Поэтому штатный `RutubeUnavailableUploadTransport`:

- сообщает код `rutube_partner_upload_api_required`;
- отмечает входящую синхронизацию готовой;
- отмечает исходящую автоматическую загрузку неготовой;
- возвращает неретраебельную ошибку;
- не выполняет сетевых запросов к неподтверждённым endpoint.

Это означает, что кодовая часть ChurchCMS завершена, но финальный релиз 1.0 и живой сквозной тест Rutube остаются заблокированы до получения официального партнёрского upload-контракта или официальной документации API.

## Подключение подтверждённого транспорта

Реализация партнёрского транспорта должна реализовать `RutubeUploadTransport` и определить:

- безопасную аутентификацию;
- официальный endpoint создания/инициализации загрузки;
- передачу бинарного файла или resumable-сессию;
- обязательные поля метаданных видео;
- правила категорий, приватности, публикации и модерации;
- формат удалённого ID и canonical URL;
- временные и постоянные классы ошибок;
- повторяемость сетевых/серверных ошибок;
- получение финального статуса обработки видео;
- ограничения частоты и параллельности.

Секреты Rutube не должны попадать в журналы, интерфейс после сохранения или диагностические сообщения.

## Проверка

Локальный smoke без сетевого доступа:

```bash
php tools/rutube-outbound-smoke.php
```

Он проверяет:

- capability `publish.video`;
- успешную работу с тестовым готовым transport;
- передачу Media-видео в transport;
- отказ при отсутствии видео;
- ограничение размера;
- допустимые MIME-типы;
- ограничение длительности при наличии метаданных;
- неретраебельность постоянных ошибок;
- явную диагностику отсутствующего официального upload API.

В CI эти сценарии выполняет workflow «Проверка исходящего Rutube».
