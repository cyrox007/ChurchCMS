# ChurchCMS 1.0.0 — черновик описания релиза

> Статус: release candidate. Этот текст нельзя публиковать как финальный релиз до прохождения внешних приёмок, performance gate и живого пилота.

## Главное

ChurchCMS 1.0 — самостоятельная PHP 8.3+ CMS для приходских, кафедральных и образовательных сайтов с единой административной оболочкой, многоуровневой структурой организаций, безопасным Media-контуром, внешним распространением и инструментами обновления/резервирования.

## Базовая платформа

- PHP 8.3+ без обязательного Composer/vendor runtime;
- PostgreSQL и MySQL;
- web-installer и healthcheck установки;
- Admin Shell, RBAC и organization-scoped права;
- CSRF/session/security headers;
- журнал аудита и production error handling;
- резервное копирование и восстановление;
- подписанный updater с rollback, включая schema-changing update;
- production-шаблоны Nginx, PHP-FPM и cron;
- ротация журналов.

## Контент

- публикации, страницы и меню;
- поиск;
- Media, галереи и документы;
- духовенство и назначения;
- богослужения и события;
- SEO, sitemap и redirects;
- revisions;
- модерируемые комментарии.

## Media Storage & Optimization

Версия 1.0 рассчитана на многолетние новостные архивы с большим количеством фотографий:

- SHA-256 дедупликация blob;
- автоматические WebP-веб-версии;
- пакетная оптимизация существующего фотоархива;
- S3-compatible архив старых оригиналов;
- проверка размера и SHA-256 перед удалением локальной копии;
- автоматическое восстановление архивного blob по прежнему публичному URL;
- dry-run освобождающих место операций;
- диагностика orphan/missing Media;
- отчёт по занимаемому месту и прогноз заполнения.

## Legacy migration

Добавлен безопасный импорт из VPDS через документированный manifest:

- dry-run;
- перенос публикаций;
- перенос Media с SHA-256;
- redirects;
- стратегия пользователей без импорта legacy-паролей;
- диагностика битых ссылок и отсутствующих Media;
- идемпотентный повторный запуск без дублей.

## Интерфейс администратора

Внутри уже открытого административного раздела большинство рабочих операций выполняется без полной перезагрузки страницы:

- сохранение и переключение состояний;
- модерация;
- загрузки;
- retry/requeue/sync;
- локальные фильтры и пагинация;
- состояния выполнения, успеха и ошибки;
- защита от повторной отправки.

Поведение проверяется реальным Chromium-сценарием.

## Требования

- PHP 8.3 или новее;
- PostgreSQL либо MySQL из поддерживаемых релизным контуром версий;
- production-развёртывание через Nginx + PHP-FPM рекомендуется для рабочего сайта;
- для фоновых очередей и обслуживания Media требуется настроенный cron;
- для внешнего Media-архива требуется S3-compatible backend.

## Перед обновлением

1. Сделать резервную копию БД и пользовательских файлов.
2. Проверить состояние текущей поддерживаемой версии.
3. Прочитать актуальную инструкцию обновления.
4. Не выполнять ручное удаление Media во время миграции.
5. После обновления проверить healthcheck, фоновые задачи, публикации и Media.

## Известные внешние зависимости кандидата

До публикации финального `1.0.0` должны быть завершены:

- официальный партнёрский upload-контракт Rutube и сквозной тест;
- партнёрская приёмка СМИ2;
- партнёрская приёмка Новости Mail;
- проверка Media archive с реальным S3-compatible backend;
- эталонный performance gate;
- живой production-подобный пилот.

После их прохождения этот раздел необходимо заменить фактическими результатами приёмки и только затем использовать документ как основу публичного описания релиза.
