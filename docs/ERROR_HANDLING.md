# Обработка ошибок

## Production-поведение

Главный front controller `index.php` подключает `core/ErrorHandler.php` **до** `core.php`.

Это позволяет перехватывать необработанные исключения и критические ошибки не только в контроллерах, но и во время bootstrap приложения.

По умолчанию `app.debug=false`.

При внутренней ошибке ChurchCMS:

- возвращает HTTP 500;
- устанавливает `Cache-Control: no-store`;
- формирует случайный request ID;
- добавляет request ID в заголовок `X-Request-ID`;
- для `/api/**`, `/health` и JSON-клиентов возвращает нейтральный JSON;
- для браузера возвращает минимальную нейтральную HTML-страницу;
- не показывает пользователю класс исключения, message, путь файла или stack trace;
- пишет подробность в server error log;
- дополнительно пишет запись в `storage/logs/error.log`, если каталог доступен для безопасной записи.

Пример production JSON:

```json
{
  "error": "internal_server_error",
  "message": "Внутренняя ошибка сервера.",
  "request_id": "0123456789abcdef01234567"
}
```

Request ID нужен оператору, чтобы сопоставить обращение пользователя с записью в журнале.

## Локальная диагностика

Подробность можно явно включить только в локальной конфигурации:

```php
'app' => [
    'debug' => true,
],
```

При `app.debug=true` error handler может добавить класс/message/file/line в ответ.

На production-сайте `debug` должен оставаться `false`.

## Что не делает обработчик

Error handler не превращает обычные PHP warnings/notices в исключения. Это сделано намеренно, чтобы production-сайт не становился недоступным из-за некритичного предупреждения.

Отдельные задачи observability/log rotation остаются в операционном backlog: текущий error log ограничивает утечку данных в HTTP-ответ, но ещё не является полноценной системой ротации/агрегации журналов.

## CI

`error-handler-smoke.yml` проверяет:

- загрузку обработчика раньше ядра;
- PHP 8.3 syntax;
- production HTML без внутренней секретной строки;
- production JSON без внутренней секретной строки;
- корректный 24-символьный request ID;
- запись внутренней подробности в приватный `storage/logs/error.log`.
