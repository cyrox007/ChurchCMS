# AJAX/UX gate ChurchCMS 1.0

## Цель

Административная часть ChurchCMS должна вести себя как современное приложение: если пользователь остаётся в текущем рабочем контексте, действие не должно вызывать полную перезагрузку документа.

Обычная навигация между самостоятельными страницами остаётся допустимой и не должна искусственно превращаться в SPA.

## Какие действия выполняются без полной перезагрузки

- POST-сохранение форм;
- создание и удаление сущностей;
- publish/unpublish/withdraw/cancel/archive;
- включение и выключение опций;
- модерация комментариев и входящих материалов;
- retry/requeue/sync/test connection;
- загрузка файлов и multipart-формы;
- изменение порядка элементов;
- массовые действия;
- действия встроенных и модальных форм;
- локальные фильтры/пагинация, когда пользователь остаётся в том же разделе.

## Допустимые исключения

Полная навигация допустима, когда она является результатом действия:

- переход в другой административный раздел или отдельный редактор;
- выход из системы;
- переход на публичный сайт;
- скачивание файла;
- внешняя авторизация/OAuth;
- действие, которому браузер обязан передать управление внешнему ресурсу.

Каждое новое исключение должно быть явным и проверяемым. Для POST-форм Admin Shell атрибут `data-no-ajax` запрещён без добавления сценария в allowlist предрелизного аудита.

## Обязательные состояния

Каждая асинхронная операция должна давать пользователю обратную связь:

1. **Выполнение** — рабочая область получает `aria-busy`, повторная отправка блокируется, показывается индикатор.
2. **Успех** — содержимое обновляется с серверного ответа и показывается краткое подтверждение.
3. **Ошибка** — пользователь видит сообщение об ошибке; серверная валидация остаётся в рабочей области.
4. **Пустой результат** — экран должен иметь осмысленное пустое состояние, если действие удалило последний элемент или фильтр ничего не нашёл.
5. **Доступность** — статус передаётся через `aria-live`; `prefers-reduced-motion` отключает необязательную анимацию.

## Progressive enhancement

AJAX является улучшением поверх обычного серверного контракта, а не отдельной логикой данных:

- серверные POST-маршруты и CSRF остаются источником истины;
- без JavaScript формы продолжают работать обычным POST + redirect;
- multipart используется через `FormData`;
- запросы выполняются только на same-origin;
- cookies/session передаются только как `same-origin`;
- серверный redirect разрешено следовать внутри `fetch`;
- после ответа заменяется только `#admin-content`, а не весь документ;
- состояние меню, счётчика задач и заголовка синхронизируется из серверного ответа.

## Автоматический gate

`php tools/admin-async-audit.php` выполняет статическую проверку всего набора административных шаблонов:

- перечисляет POST-формы Admin Shell;
- проверяет подключение общего AJAX-слоя;
- проверяет наличие `loading/success` контракта;
- запрещает необъяснённые `data-no-ajax`;
- разрешает штатное исключение для выхода из системы.

Проверка входит в `php bin/release-audit.php` и поэтому становится частью RC 1.0.

Дополнительно `.github/workflows/admin-async-browser-smoke.yml` запускает настоящий Chromium через Playwright. Браузерный smoke использует реальный `themes/default/assets/js/admin-async.js` и проверяет:

- POST + redirect без перезагрузки документа;
- multipart-загрузку через `FormData`;
- обязательные AJAX-заголовки;
- `aria-busy`, состояние выполнения и блокировку кнопки;
- успешное состояние после операции;
- GET-фильтр без перезагрузки;
- пагинацию без перезагрузки;
- восстановление содержимого через Back/Forward и `popstate`;
- отображение серверной ошибки без перезагрузки;
- обычную навигацию при переходе в другой раздел;
- явный `data-no-ajax` как обычную отправку формы.

Таким образом gate проверяет и охват шаблонов, и реальное поведение DOM в браузере.

## Ручной проход перед живым развёртыванием

Автоматические проверки не заменяют последний проход по реальному установленному ChurchCMS. Перед первым живым развёртыванием необходимо пройти по всем административным разделам и для каждого изменяющего действия подтвердить:

- страница целиком не перезагружается;
- двойной клик не создаёт дубль;
- успешное состояние отображается;
- ошибка сети/серверная ошибка отображается;
- ошибки валидации не теряют введённые данные;
- списки и счётчики обновляются после операции;
- фокус остаётся предсказуемым;
- клавиатурная навигация продолжает работать;
- multipart upload не ломается;
- logout/OAuth/download работают через обычную навигацию.

Последний ручной проход выполняется уже на пилотной установке после завершения всего функционального объёма 1.0 и не заменяет текущий автоматизированный браузерный gate.
