# Административная аутентификация

## Вход

ChurchCMS использует `password_hash/password_verify` и автоматически перехеширует пароль при успешном входе, если текущие параметры PHP требуют обновления.

После успешной аутентификации сессия получает:

- ID администратора;
- public ID;
- время аутентификации;
- текущую `auth_version`.

## Ротация пароля

Авторизованный администратор может открыть «Аккаунт → Смена пароля».

Для смены требуется:

- текущий пароль;
- новый пароль не короче 12 символов;
- повтор нового пароля;
- новый пароль должен отличаться от текущего;
- запрос защищён CSRF.

После успешной смены:

1. новый password hash сохраняется в БД;
2. `auth_version` пользователя увеличивается;
3. текущий session ID регенерируется;
4. текущая сессия получает новую `auth_version`;
5. CSRF token ротируется;
6. действие записывается в audit log.

## Отзыв старых сессий

Каждый защищённый admin-запрос сравнивает `admin_auth_version` из сессии с `admin_users.auth_version`.

После смены пароля все другие сессии содержат старое значение и на следующем запросе считаются недействительными. Это даёт отзыв старых сессий без обязательного централизованного session-store.

Сессии, созданные до появления `auth_version`, также потребуют повторного входа после обновления схемы.

## Что ещё не реализовано

Forgotten-password flow пока не считается готовым.

ChurchCMS не отправляет reset token через непроверенный или несуществующий почтовый транспорт и не пишет временный пароль в лог. Следующий инкремент должен определить безопасный канал доставки одноразового подтверждения либо административный reset workflow с явным принудительным сбросом.
