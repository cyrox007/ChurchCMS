# Административная аутентификация

## Вход

ChurchCMS использует `password_hash/password_verify` и автоматически перехеширует пароль при успешном входе, если текущие параметры PHP требуют обновления.

После успешной аутентификации сессия получает:

- ID администратора;
- public ID;
- время аутентификации;
- текущую `auth_version`.

## Ротация пароля

Авторизованный администратор может открыть «Аккаунт → Смена пароля».

Для смены требуется:

- текущий пароль;
- новый пароль не короче 12 символов;
- повтор нового пароля;
- новый пароль должен отличаться от текущего;
- запрос защищён CSRF.

После успешной смены:

1. новый password hash сохраняется в БД;
2. `auth_version` пользователя увеличивается;
3. текущий session ID регенерируется;
4. текущая сессия получает новую `auth_version`;
5. CSRF token ротируется;
6. действие записывается в audit log.

## Отзыв старых сессий

Каждый защищённый admin-запрос сравнивает `admin_auth_version` из сессии с `admin_users.auth_version`.

После смены пароля все другие сессии содержат старое значение и на следующем запросе считаются недействительными. Это даёт отзыв старых сессий без обязательного централизованного session-store.

Сессии, созданные до появления `auth_version`, также потребуют повторного входа после обновления схемы.

## Восстановление забытого пароля

Публичный flow использует:

- `GET /admin/password/forgot` — форма запроса;
- `POST /admin/password/forgot` — выдача одноразовой ссылки;
- `GET /admin/password/reset?token=...` — проверка ссылки и форма нового пароля;
- `POST /admin/password/reset` — одноразовое применение нового пароля.

Токен содержит 256 бит криптографически случайных данных. В таблице
`admin_password_resets` хранится только SHA-256 токена, срок действия,
состояние использования и ссылка на администратора. Plaintext-токен не
записывается ни в БД, ни в audit log.

Новый запрос инвалидирует предыдущие неиспользованные токены пользователя.
Ссылка одноразовая и по умолчанию действует 30 минут. После успешного reset:

1. пароль хешируется через `PASSWORD_DEFAULT`;
2. токен атомарно помечается использованным;
3. остальные reset-токены пользователя инвалидируются;
4. `auth_version` увеличивается;
5. все ранее открытые административные сессии теряют действительность.

Форма запроса всегда показывает одинаковый результат для существующего и
несуществующего email. POST-запросы дополнительно защищены CSRF и отдельным
rate-limit по IP + хэшу email/токена.

## Канал доставки

По умолчанию доставка отключена. ChurchCMS не выводит reset URL в лог и не
возвращает его браузеру.

Для встроенного native mail transport в `config/local.php` нужно явно задать:

```php
'security' => [
    'password_reset' => [
        'transport' => 'mail',
        'mail_from' => 'no-reply@example.org',
        'ttl_seconds' => 1800,
    ],
],
```

Хост должен иметь рабочий PHP `mail()` transport. Если доставка завершается
ошибкой, только что созданный токен немедленно инвалидируется, а пользователь
всё равно получает нейтральный внешний ответ.

`PasswordResetTransport` является отдельным контрактом, поэтому SMTP/API
доставку можно подключить позднее без изменения reset-ядра.
