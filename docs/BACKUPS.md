# Резервное копирование и обновления

Этот документ описывает текущий фундамент резервного копирования ChurchCMS. Полный мастер обновления ещё не завершён.

## Где хранятся копии

По умолчанию ChurchCMS создаёт каталог резервных копий рядом с каталогом сайта:

```
/var/www/churchcms
/var/www/churchcms-backups
```

Копии намеренно не разрешается хранить внутри публичного корня ChurchCMS.

Путь можно переопределить в локальной конфигурации через `operations.backup_path`. Для технической диагностики CLI также принимает `--path=/абсолютный/путь`.

## Что входит в копию

Текущий формат `churchcms-backup-v1` содержит:

- `config/local.php`;
- файлы из `storage/uploads`;
- логический снимок всех обычных таблиц текущей PostgreSQL/MySQL базы;
- `manifest.json` с версией ChurchCMS, временем создания, размерами и SHA-256.

Для БД не требуются внешние `pg_dump` или `mysqldump`. Данные читаются через PDO. Значения строк сохраняются как base64-or-null, чтобы будущий restore мог восстановить в том числе бинарные значения без перекодирования.

Символические ссылки в резервируемых данных запрещены: это исключает случайное копирование файлов за пределами сайта.

## Создание копии

Технический резервный способ:

```bash
php bin/backup.php create
```

Успешной считается только копия, которая прошла проверку манифеста и всех контрольных сумм до финального переименования каталога.

## Повторная проверка

```bash
php bin/backup.php verify 20260926T123456Z-012345abcdef
```

Команда не принимает произвольный путь к копии: идентификатор имеет строгий формат, а корневой каталог задаётся настройкой ChurchCMS.

## Что пока не реализовано

До закрытия общего пункта Update/backup workflow остаются:

- восстановление таблиц, sequence/auto_increment, конфигурации и uploads;
- тест восстановления на чистой базе;
- staging и проверка пакета обновления;
- безопасная замена файлов приложения;
- запуск миграций после замены;
- обязательный healthcheck;
- автоматический откат при неудачном обновлении;
- простой мастер в Admin Shell.

До появления restore резервная копия является проверенным снимком данных, но не должна считаться завершённым механизмом аварийного восстановления.
